**Scope source:** `paranagua_truck_evidence.txt` (canonical Steps 1–10 road/truck consolidation + Step 8 road/truck hinterland + 0.00C canonical rules). Analysis restricted to that file only; no outside knowledge used.
**Produced:** 2026-08-29 — PortX Intelligence
**Method:** one row per canonical entity/terminal/operator present in the dossier with truck/road access-control evidence. Aliases deduplicated to a single canonical name. Where a truck/road access-control capability exists but no software/system is identified in the dossier, the row states `not identified in dossier` in the Software/system column. Source line ranges use the dossier's own canonical (bracketed) line numbering; Source section is the dossier heading.

## Evidence-status legend
- **CONFIRMED** — system/software and (where applicable) vendor identified and current in-document.
- **CONFIRMED (system name) / SW NOT IDENTIFIED** — named system layer exists, but the software product or vendor is not identified.
- **PARTIAL** — control class/process evidenced, but software/product left open.
- **FUTURE / NOT CURRENT** — capability is planned/scheduled, not current.
